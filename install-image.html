Route 1 · recommended

Flash the ready image

One download, everything inside: kernel, hardware fixes, the six own applications, browser, mail, maps, photos. About 1.2 GB compressed, 6.1 GB once unpacked: keep 8 GB free on the PC before you start.

Download utsugi-surya-v2026.09.17.img.xz — 1.2 GB

Four steps come before the flashing, and the first one takes a week. Unlock the bootloader at Xiaomi, find out which screen your phone has, put U-Boot on it, and get fastboot on your PC. They are all below, in order.
01

Unlock the bootloader at Xiaomi

The phone refuses to boot anything but MIUI until Xiaomi lets it. It needs a Mi account, seven days of waiting, and it erases the phone. Start it today; the rest of this page takes twenty minutes once it is done.

It does not need Windows: miunlock (MiUnlockTool) does it from Linux.

The unlock, step by step →

02

Find out which screen you have

The POCO X3 NFC shipped with two panels, Tianma and Huaxing, and U-Boot comes as one build per panel. The wrong one boots fine and draws nothing at all.

From MIUI, with USB debugging on (the developer options you turned on while unlocking) and adb installed:

IN A TERMINAL ON YOUR PC
adb shell cat /proc/cmdline | tr ' ' '\n' | grep -i dsi
# Windows PowerShell: .\adb shell "cat /proc/cmdline" , then look for dsi

Xiaomi's kernel names the panel in there: the line carries tianma or huaxing. If nothing useful comes out, or there is no MIUI left to ask because the phone already runs some Linux, flash one and look at the screen — black means the other one, and you can reflash as often as you like.

03

Get fastboot on your PC

Debian/Ubuntuapt install android-sdk-platform-tools
Archpacman -S android-tools
Fedoradnf install android-tools
Alpineapk add android-tools
Windows / macOSplatform-tools from developer.android.com; on Windows also the Google USB driver. The front page has the commands for both.

And a data cable, straight into the computer if you can: hubs cause half the "device not found".

04

U-Boot on boot

This port does not boot a kernel from the boot partition — it boots U-Boot from there, and U-Boot loads the system from userdata. So boot is written once, with U-Boot, and never again.

Take the image for your panel from sm7150-mainline/u-boot, put the phone in fastboot — off, then volume-down + power — and:

IN A TERMINAL
sudo fastboot devices        # must print your phone
sudo fastboot erase dtbo     # MIUI's overlay would fight U-Boot
sudo fastboot flash boot u-boot-sm7150-xiaomi-surya-tianma.img
sudo fastboot reboot
IN POWERSHELL
.\fastboot devices           # must print your phone
.\fastboot erase dtbo        # MIUI's overlay would fight U-Boot
.\fastboot flash boot u-boot-sm7150-xiaomi-surya-tianma.img
.\fastboot reboot
# not tested by me: reports welcome
IN A TERMINAL
fastboot devices             # must print your phone
fastboot erase dtbo          # MIUI's overlay would fight U-Boot
fastboot flash boot u-boot-sm7150-xiaomi-surya-tianma.img
fastboot reboot
# not tested by me: reports welcome

Power on: you should get a text console complaining it has nothing to boot. That complaint is the good outcome — there is no system on userdata yet. A screen that stays black means the other panel.

Already running this system, or a postmarketOS you installed through U-Boot? Then U-Boot is there and this step is done. Not sure what is on boot? Do the step anyway: fastboot cannot tell you what is in there, writing U-Boot a second time does no harm, and a plain postmarketOS made with pmbootstrap keeps a kernel in boot, which this image cannot boot from.

05

Put the phone in fastboot

Turn it off. Then hold volume-down + power until the screen says fastboot, and plug the cable in. If the phone already runs this system, sudo reboot-to-bootloader on the phone does the same thing.

ON YOUR PC
sudo fastboot devices
# prints something like:  83d9a95b   fastboot
# nothing? another cable, another port, and check the phone is really
# in fastboot and not just off.

sudo because without udev rules the device belongs to root.

06

Flash it

Your data is gone from here on: this writes the whole system partition.

IN A TERMINAL
xz -d utsugi-surya-v2026.09.17.img.xz            # a half-downloaded file fails right here

sudo fastboot flash userdata utsugi-surya-v2026.09.17.img   # userdata. never boot.
sudo fastboot reboot

sudo because without udev rules the device belongs to root. Install android-udev-rules and you can drop it.

IN POWERSHELL
7z x utsugi-surya-v2026.09.17.img.xz             # or any unzipper that knows .xz

.\fastboot flash userdata utsugi-surya-v2026.09.17.img   # userdata. never boot.
.\fastboot reboot
# not tested by me: reports welcome

Run it from the folder platform-tools unpacked into, and install the Google USB Driver first or fastboot devices prints nothing. Windows has no xz: 7-Zip opens it.

IN A TERMINAL
xz -d utsugi-surya-v2026.09.17.img.xz            # brew install xz, if you have none

fastboot flash userdata utsugi-surya-v2026.09.17.img   # userdata. never boot.
fastboot reboot
# not tested by me: reports welcome

No sudo: macOS needs no udev rules. Get the tools with brew install --cask android-platform-tools, or unpack platform-tools and call it as ./fastboot.

What to expect while it runs, so nothing looks broken:

xz -dA minute or two, no output. It replaces the .xz with a 6.1 GB .img.
fastboot flashAbout three minutes: six Sending sparse 'userdata' lines, each ending in OKAY. A Warning: skip copying userdata image avb footer with an absurd image size comes first. It is harmless; ignore it.
fastboot rebootCan sit for up to a minute before it prints OKAY. Keep the cable in; it has not hung.
The phoneA black screen for a while, then the desktop. First boot takes a minute longer than the rest.
Log in and change the password. The image ships user user with password 1111, because an image has to have one and it is printed on this page — so anybody who can read knows the password of a phone that has not changed it. Change it in Settings → Users, or in a terminal: passwd.

The phone asks you to, and it does not ask politely: the first session opens full screen on a step that wants a new password before anything else. Pick anything you like, a 4-digit PIN included; once you set it the step never comes back.
Then it asks whether to encrypt the phone. Say yes and choose a passphrase, plug the charger in, and it restarts and encrypts the storage in place before anything is mounted. From then on every start asks for the passphrase on the screen, before the PIN.

It is done on the phone, so the LUKS key is born there and no computer is involved — which is also why no encrypted image is offered for download: one made on someone else's machine would carry a key that machine had seen. It reads and writes every sector once, so it takes twenty to forty minutes with a percentage on screen; keep the charger in and do not turn it off. If it dies halfway the next boot asks for the passphrase and finishes what was left, and nothing is lost. The passphrase cannot be recovered: forget it and the data is gone.

“Not now” is for good — the question does not come back — but you can still encrypt later from a terminal on the phone, which runs the same thing the assistant would:
ON THE PHONE
printf 'your passphrase' | pkexec /usr/libexec/utsugi-surya/request-encryption
